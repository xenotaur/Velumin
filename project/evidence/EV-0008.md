# EV-0008: Blasterites Demos and Vector CRT Renderer Code Verification

## Summary
- Verified, by inspection of the merged source as of 2026-07-24 (the Blasterites demo and renderer work merged across PRs #3-#6), that the Blasterites tester and tuner demos (DP-0005) are implemented, and that substantial parts of the Vector CRT renderer (DP-0006) have already landed.
- This evidence is grounded in the merged source at that date, not in a fresh browser visual smoke run. Browser/screenshot smoke validation of the demo scenes remains follow-up work.

## Code Verified
- `webgpu_vector_lib/src/lib.rs`
  - `pub fn render()` — the preserved white-line baseline entrypoint (DP-0001) is still present.
  - `pub fn render_blasterites_tester(&mut self, time_ms: f64)` — deterministic tester keyed to a wrapped Blasterites cycle time (`BLASTERITES_CYCLE_MS`).
  - `pub fn render_blasterites_tuner(...)` — tester variant driven by live line-width and glow-layer parameters.
  - `enum VectorDisplayPreset { ArcadeBalanced, MonochromeBeam, ColorQuadraScan, CleanNeon }` with per-preset glow-layer tables (currently internal / `#[allow(dead_code)]`, wired to the tester and tuner rather than to a public preset selector).
  - `RenderViewport::centered_4_3(..)` with `TARGET_ASPECT = 4.0 / 3.0`, applied to both the glow and surface passes so window resizing letterboxes rather than distorts the scene.
- `webgpu_vector_lib/web/index.html`
  - Query-parameter routing: `?demo=blasterites` calls `render_blasterites_tester`; `?demo=tuner` calls `render_blasterites_tuner` and exposes the tuner control panel; default renders the baseline.
- `webgpu_vector_lib/shaders/` — `line.wgsl`, `glow.wgsl`, `composite.wgsl`, `tester_composite.wgsl` (tester-only scanline/post-process composite).
- `scripts/demos` — builds the WASM package and serves the `baseline`, `blasterites`, and `tuner` routes via Vite.

## Result
- DP-0005 (Blasterites tester + tuner demos) is implemented in the merged code.
- DP-0006 (Vector CRT renderer migration) is partially implemented: the fixed 4:3 logical viewport, additive multi-layer glow compositing, and named display presets exist internally; the Arcade Balanced preset is the tuned default target. Public entrypoints from DP-0001 are preserved as DP-0006 required.
- A unit test, `centered_viewport_preserves_four_by_three_aspect`, covers the viewport aspect behavior.

## Remaining Follow-up
- Record a browser/screenshot visual smoke run for `/?demo=blasterites` and `/?demo=tuner` at known deterministic moments.
- Decide whether the internal `VectorDisplayPreset` set should become a public, selectable API as part of completing DP-0006.
