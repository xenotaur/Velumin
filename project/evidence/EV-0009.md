# EV-0009: Blasterites Demos Browser Visual-Smoke Capture

## Summary
- Captured browser visual-smoke evidence for the Velumin demos by building the WASM package, serving the Vite harness, and rendering each scene through the real `WebGPU` entrypoints.
- The baseline, Blasterites tester, and tuner scenes all render as expected on a WebGPU backend with no console errors.
- The tester was captured at two deterministic cycle moments (pre-impact and post-impact) so future screenshot smoke checks can target the same frames.

## Environment
- Build: `npm run build:wasm` (wasm-pack 0.13.1) then `npm run dev` (Vite 6.2.2) from `webgpu_vector_lib/web/`.
- Server: `http://127.0.0.1:5173/`.
- Browser: Chromium-based (Claude in-app browser, Chrome 148 / Electron), `navigator.gpu` present.
- WebGPU adapter: vendor `apple`, architecture `metal-3`; adapter features include `depth32float-stencil8`, `rg11b10ufloat-renderable`, `texture-formats-tier1`.
- Canvas: fixed `800x600` (already 4:3).

## Deterministic Timing
- `BLASTERITES_CYCLE_MS = 5600`, `BLASTERITES_IMPACT_MS = 3000` (see `webgpu_vector_lib/src/lib.rs`).
- Frames were rendered at fixed elapsed-time values by calling `render_blasterites_tester(t)` once per load through a temporary single-frame page (not committed), rather than sampling the live animation loop.

## Scenes Verified
- Baseline `/` (`render()`): a single crisp white vector line with a soft glow on a black field. Not all-black, not all-white.
- Blasterites tester at `t = 2000 ms` (pre-impact, wrapped 2000/5600): glowing arrow ship (rotated), a bright bullet in flight, and an approaching irregular closed asteroid polygon.
- Blasterites tester at `t = 4000 ms` (post-impact, wrapped 4000/5600): the asteroid is gone and replaced by a radial spark explosion of colored particles; the ship has rotated to a new heading.
- Tuner `/?demo=tuner` (`render_blasterites_tuner(...)`): the same tester scene with the live control panel visible and all seven glow/stroke sliders at their default values (line width 0.35, near 2.2/0.33, mid 5.0/0.12, far 12.3/0.03).

## Result
- All three demo routes render visibly and correctly; the deterministic tester frames match the expected pre-impact and post-impact phases.
- `read_console_messages` reported no errors during rendering.
- This closes the browser visual-smoke gap noted in `EV-0008` for the demo scenes (DP-0005), and provides first visual confirmation of the DP-0006 renderer output (additive glow on a black field).

## Captured Frames
- `project/evidence/EV-0009/blasterites_t2000.png` — tester at `t = 2000 ms` (pre-impact).
- `project/evidence/EV-0009/blasterites_t4000.png` — tester at `t = 4000 ms` (post-impact spark explosion).
- The baseline and tuner scenes were verified live and are described above; only the two deterministic tester frames are committed as image artifacts.

## Scope Notes / Remaining Follow-up
- The demo canvas is a fixed `800x600` (4:3) surface, so these captures do not exercise the `RenderViewport::centered_4_3` letterbox path for non-4:3 surfaces; that path remains covered by the unit test `centered_viewport_preserves_four_by_three_aspect`, not by this visual capture.
- Only the internal `ArcadeBalanced`-style default and the tuner path were exercised; the other `VectorDisplayPreset` values (`MonochromeBeam`, `ColorQuadraScan`, `CleanNeon`) are not yet selectable from the demos and were not visually captured.
- A committed, automatable screenshot smoke check (e.g. a headless capture at these deterministic times) is still future work.
