# Summary

Implements WI-ARCH-0001 (DP-0002 Phase 1): converts the repository into a
Cargo workspace and extracts a new `velumin-core` crate holding Velumin's
platform-neutral vector/scene/style types, with zero
`wasm-bindgen`/`web-sys`/`wgpu` dependency. `webgpu_vector_lib` keeps the
`wgpu` renderer and browser adapter, now depending on `velumin-core`. Crate
rename remains explicitly deferred per the 2026-07-30 scoping decision in
`project/memory/decision_log.md`.

# Result

Created `velumin-core/Cargo.toml` (no dependencies) and
`velumin-core/src/lib.rs`, moving `Vec2`, `Color`, `StrokeStyle`, `Line`,
`Polyline`, `VectorCommand`, `VectorDisplaySettings`, `GlowLayer`,
`RenderViewport`, and the pure geometry helpers `transform_points`,
`lerp_vec2`, `stroke` out of `webgpu_vector_lib/src/lib.rs`. Added a root
workspace `Cargo.toml` (`members = ["webgpu_vector_lib", "velumin-core"]`).
`webgpu_vector_lib` now depends on `velumin-core` via a path dependency and
re-exports the moved types with `pub use velumin_core::{...}`, so the public
WASM API surface (`create`, `createWithPreset`, `setDisplayPreset`, the
preset enum, vector command types) is unchanged for JS/Rust consumers.

Deviation from the work item's literal Required Changes, flagged and
approved at the plan-confirmation gate: `VectorDisplayPreset` stays in
`webgpu_vector_lib` rather than moving to `velumin-core`, because it is
`#[wasm_bindgen]`-exported and used as a parameter type on wasm-bindgen
methods, while `velumin-core` must have zero wasm-bindgen dependency (an
explicit acceptance criterion). The four preset-to-glow-layer-table constants
and a new free function, `display_settings_from_preset`, bridge preset
selection to the moved `VectorDisplaySettings::from_layers` constructor.

Updated `scripts/format`, `scripts/lint`, `scripts/test` to target the
workspace root manifest (`scripts/baseline`, `scripts/demos`,
`scripts/smoke`, and `.github/workflows/validate.yml` needed no changes —
already crate-specific or manifest-agnostic). Updated `README.md` and
`scripts/README.md` to describe the two-crate workspace layout.

Fixed a Cargo.lock version-drift regression discovered during
implementation: introducing the workspace root triggered full dependency
re-resolution the first time `cargo` ran against it, bumping `wasm-bindgen`
from the previously pinned 0.2.121 to 0.2.126 and breaking `scripts/baseline`
(`wasm-bindgen-cli`'s transitive `time` crate requiring rustc 1.88 vs. the
repo's pinned 1.87.0). Fixed by discarding the freshly-resolved lockfile and
reusing the existing pinned one at the new root path
(`git mv webgpu_vector_lib/Cargo.lock Cargo.lock`), confirmed via
`git diff --stat` that only the new `velumin-core` entry was added with no
other version drift.

Opened as PR #17 (branch `xenotaur/feat/wi-arch-0001`).
