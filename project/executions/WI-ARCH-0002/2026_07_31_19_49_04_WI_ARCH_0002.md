# Summary

Implements WI-ARCH-0002 (DP-0002 Phase 2's scoped first slice): makes
`webgpu_vector_lib`'s `Renderer` compile and construct on the host target,
not just `wasm32-unknown-unknown` behind wasm-bindgen.

# Result

Added `RendererError` (a platform-neutral `String`-wrapping error type
implementing `std::error::Error`), replacing `JsValue` as the error type on
`Renderer::new` and `Renderer::render`. Added a `From<RendererError> for
JsValue` impl (wasm32-gated) so `?` inside `WebGPU`'s wasm-bindgen methods
auto-converts; the three render entrypoints (`render`,
`render_blasterites_tester`, `render_blasterites_tuner`) use
`.map_err(JsValue::from)` at their tail expression.

Added `renderer_log`, a platform-neutral logging shim (forwards to the
wasm-bindgen `console.log` binding on wasm32, no-op on host), replacing
`Renderer`'s direct `log(...)` calls.

Removed `#[cfg(target_arch = "wasm32")]` from `Renderer`'s struct and impl
block, and from every item in its construction/render/resize dependency
chain — exactly the set enumerated during the work item's scoping (verified
unchanged against the work item text): the `RenderViewport` import,
`Vertex`/`GlowVertex`'s `ATTRIBUTES` consts and `layout()` methods, and the
free functions `create_vector_pipeline`, `create_glow_pipeline`,
`additive_blend_state`, `create_composite_pipeline`, `create_glow_target`,
`upload_vertices`, and `upload_glow_vertices`. Added matching
`#[cfg_attr(not(wasm32), allow(dead_code))]` to each so host builds stay
warning-free, since only `WebGPU` (still wasm32-gated) calls into these on
the current call graph.

`WebGPU` (canvas lookup, `wgpu::SurfaceTarget::Canvas`, resize-from-window)
stays wasm32-gated exactly as before, unchanged.

Updated `README.md`'s Repository Orientation and Browser Rendering Baseline
sections to describe `Renderer` as host-buildable, not just `velumin-core`.
`scripts/README.md` needed no change — its existing wording didn't
misstate anything about `Renderer`.
